\section{Use Case Scenarios}
\label{sec:usecases}

\InputIfFileExists{figures/usecase}{}{}

\Cref{fig:usecase} shows the use cases. The main flow is:
\begin{enumerate}
  \item The user imports a sheet (or a sample).
  \item QLens shows keys, dependencies and data problems; the user fixes the problems.
  \item QLens proposes a 3NF design; the user may rename tables or columns.
  \item The user applies the design: the tables are created, filled and checked in one transaction.
  \item The user browses and edits the new tables and queries them with SQL on the Data page, and asks questions in plain English on the Ask AI page.
\end{enumerate}

\section{Other Software Engineering Methodologies}
\label{sec:methodologies}

\paragraph{Incremental, test-first development.} QLens was built in small steps in order of value:
database and accounts, import, analysis, clean-up, design, apply, querying. For each step the tests were
written first. One example: a randomized test showed that the decomposition lost rows in 74 of 3{,}000
random cases when no table contained a candidate key, which is why the algorithm adds a key table
(\cref{alg:synthesis}). The database schema is created by numbered SQL migration files, so every
computer gets exactly the same schema.

\paragraph{Test results.} Tests run against a real PostgreSQL database because most of the logic is
in SQL (\cref{tab:tests}).
