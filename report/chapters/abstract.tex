\markboth{Abstract}{}

Many small offices keep all their records in one large spreadsheet. A coaching institute's fee
register, for example, repeats every teacher's phone number on hundreds of rows and spells some
students' names in more than one way. In database terms the sheet is an unnormalized relation, and it
suffers from update, insertion and deletion anomalies. The people who use it do not know how to design
a database, so the problem stays.

QLens is a web application that designs a relational database \emph{from the data in the sheet}. It
loads the sheet into PostgreSQL, finds the functional dependencies and candidate keys by running SQL
queries on the data, and helps the user correct spelling variants and conflicting values. From the
dependencies it computes a canonical cover and applies the 3NF decomposition algorithm, which gives
tables that are in third normal form, preserve the dependencies and have a lossless join. QLens then
creates these tables with primary keys, foreign keys and \code{UNIQUE} constraints, copies the data into
them inside a single transaction, and keeps the result only if joining the new tables back together
gives exactly the original rows. Afterwards the user can browse and edit the new tables, where the
database's constraints reject bad changes and a trigger records every change, and can run SQL as a
restricted database user.

QLens stores its own data in a normalized PostgreSQL schema that uses most topics of the course:
an ER model converted to relational tables, keys and integrity constraints, views, triggers, cursors,
stored functions, indexes, transactions and GRANT-based access control. On the sample fee register
(3{,}000 rows) QLens finds every planted error and produces the expected four tables (students,
batches, teachers and fee records), and rebuilds all 3{,}000 rows exactly. 507 backend and 204 frontend
automated tests pass.

\medskip
\noindent\textbf{Keywords:} relational database design, functional dependency, normalization,
third normal form, lossless join, dependency preservation, SQL, PostgreSQL.
