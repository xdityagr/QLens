\chapter{Conclusion}
\label{ch:conclusion}

QLens shows that a database can be designed from the data itself. Starting from one spreadsheet, it
finds functional dependencies and candidate keys with SQL, helps the user correct inconsistent values,
computes a canonical cover, and applies the 3NF decomposition algorithm. The resulting tables are in
third normal form, preserve the dependencies, and are created and filled in a single transaction that
is kept only if the lossless-join check passes on the real rows. On the sample fee register all 13
faulty rows are found and the expected four tables rebuild all 3{,}000 rows exactly.

QLens's own data is also a normalized relational design, built from an ER model, with primary and
foreign keys, \code{CHECK} and \code{UNIQUE} constraints, views, triggers, stored functions, a cursor,
B-tree indexes, transactions and \code{GRANT}-based security. 507 backend and 204 frontend tests pass.

\paragraph{What we learnt.}
\begin{itemize}
  \item Real data is never perfect: a dependency may fail on a few rows because of typing errors, so
  data must be cleaned before it is normalized.
  \item Letting the database do the work (\code{GROUP BY}, constraints, transactions) keeps the
  application simple and the result correct.
  \item Constraints catch mistakes early; for example, a design cannot be marked applied unless its
  lossless-join check passed.
  \item Lossless join, a theorem in the textbook, can be checked with one SQL query.
\end{itemize}

\paragraph{Limitations.}
\begin{itemize}
  \item Dependencies are searched with at most two columns on the left-hand side and keys with at most
  three columns; one sheet is normalized at a time and only up to 3NF.
  \item Analysis was tested on the samples (up to about 3{,}000 rows). A sheet near the import limit
  (100{,}000 rows, 60 columns) can be imported, but its analysis has not been measured and may be slow.
  \item Query results are cut at 1{,}000 rows, but not by size, so very wide rows can still make a large
  result.
  \item The optional assistant sends the question, the table structure and up to 50 result rows to
  Google Gemini; the free tier allows only about 20 requests a day.
  \item The results come from sample data, not a study with real users.
\end{itemize}

\paragraph{Future work.} Support several sheets at once, detect multivalued dependencies for 4NF, and
suggest indexes automatically from the query history.
